# Claimable Balance Predicate Builder

A visual tool for building claimable balance predicates with AND, OR, NOT, and time conditions, generating plain-language previews and XDR encoding — entirely client-side.

## What it does

This tool lets users construct claim predicates without writing code or manually assembling XDR. The user builds a tree of conditions, sees what it means in plain English, and gets the encoded `xdr.ClaimPredicate` ready to use.

## Why predicates are hard

Claim predicates control who can claim a claimable balance and when. They are powerful but error-prone:

- A predicate can be accidentally inverted (NOT in the wrong place)
- Nested AND/OR logic is easy to misread
- Time conditions mix absolute and relative semantics
- Mistakes may not surface until a claim fails on-chain

This tool makes the predicate structure **visual** and **understandable**, reducing the chance of logical errors.

## Architecture

The tool follows a clean separation:

```
User Input
    ↓
RawPredicateForm (validation in schema.ts)
    ↓
PredicateNode (internal tree model in types.ts)
    ↓
Plain-language description (describePredicate in predicateBuilder.ts)
    ↓
xdr.ClaimPredicate (nodeToClaimPredicate in predicateBuilder.ts)
    ↓
Base64 XDR (toXDR("base64"))
```

The internal `PredicateNode` type is independent from:
- UI state (managed by `PredicateBuilderForm`)
- XDR objects (built by `nodeToClaimPredicate`)

This separation makes each layer testable in isolation.

## Supported predicate types

### Unconditional
Always claimable. No conditions.

### Before Absolute Time
Claimable before a specific UTC timestamp (e.g., Jan 1, 2027 00:00:00 UTC).

Uses `xdr.ClaimPredicate.claimPredicateBeforeAbsoluteTime(xdr.Int64)`.

### Before Relative Time
Claimable within N seconds after the balance was created.

Uses `xdr.ClaimPredicate.claimPredicateBeforeRelativeTime(xdr.Int64)`.

### AND
All nested conditions must be satisfied.

Requires at least 2 children. Uses `xdr.ClaimPredicate.claimPredicateAnd([...])`.

### OR
At least one nested condition must be satisfied.

Requires at least 2 children. Uses `xdr.ClaimPredicate.claimPredicateOr([...])`.

### NOT
Negates the nested condition.

Requires exactly 1 child. Uses `xdr.ClaimPredicate.claimPredicateNot(predicate)`.

## Plain-language generation

The plain-language preview is generated by `describePredicate()`, which recursively walks the `PredicateNode` tree and converts it into human-readable English.

Example:

```typescript
{
  type: "and",
  children: [
    { type: "before_absolute", timestamp: 1735689600 },
    { type: "unconditional" }
  ]
}
```

Becomes:

> the claim is made before 2027-01-01 00:00:00 UTC AND the balance can be claimed at any time

The wording for NOT is especially careful to avoid accidentally reversing the user's intent.

## XDR encoding

The XDR encoder (`nodeToClaimPredicate`) converts the internal tree to `xdr.ClaimPredicate` using the Stellar SDK.

All encoding happens **client-side**. No server is involved.

The output is deterministic: the same predicate tree produces the same XDR every time.

## Validation

Validation happens in `schema.ts` before encoding:

- **Timestamps**: Must be valid ISO 8601 dates
- **Durations**: Must be positive integers (seconds)
- **AND/OR**: Must have at least 2 children
- **NOT**: Must have exactly 1 child

Invalid predicates are rejected early with clear error codes. The error codes map to user-facing copy in `copy.ts`.

## Local-only guarantee

This feature is **completely local**:

- No backend API
- No server requests for predicate generation
- No database persistence
- No data transmission

The entire workflow runs in the browser using the `@stellar/stellar-sdk` package.

## Edge cases

### Empty predicate
Rejected with `empty_predicate` error.

### Single-child AND/OR
Rejected. AND and OR require at least 2 children because a single child is logically equivalent to the child itself.

### NOT NOT ... (multiple negations)
Allowed. Each NOT wraps the child predicate. The plain-language preview shows nested "NOT (...)" correctly.

### Deep nesting
No depth limit. The recursive encoder handles arbitrarily nested predicates.
